# Data Collection

Generated by `src/data/collector.py`
Input: GitHub REST API
Output: `data/raw/github_repositories.csv`

---

## Overview

This script collects raw data from the GitHub REST API. It queries the top 1,000 public repositories that have at least 50 stars, extracting 24 features for each repository.

---

## Execution

```bash
python3 collector.py
```

---

## How It Works

### Pagination Trick for Heavy Metrics
GitHub's API does not provide a direct total count for nested resources like commits, contributors, or pull requests directly on the repository object. 

To count these efficiently without downloading large amounts of data, the script uses a pagination technique. By requesting exactly 1 item per page (`per_page=1`), the API returns a `Link` header containing the last page number. Since there is 1 item per page, this page number directly corresponds to the total count, allowing the script to retrieve the number in a single request per metric.

### Rate Limit Management
Data collection is divided into two phases:
1. **Search Phase:** Identifies the top 1,000 repositories and retrieves their basic metrics (e.g., stars, forks, languages).
2. **Metrics Phase:** Fetches the resource-intensive metrics (`commits`, `contributors`, `releases`, `open_pull_requests`) using the pagination technique described above.

To manage API limits securely, the script monitors the `X-RateLimit-Remaining` header. If the limit reaches zero, it calculates the required wait time based on `X-RateLimit-Reset` and pauses execution. It also handles GitHub's secondary rate limits by respecting the `retry-after` header if triggered, resuming automatically once the penalty period ends.

## Collected Features

The script produces `github_repositories.csv`. The features fall into four categories:

| Category | Collected Features |
|---|---|
| Identifiers & Target | `name`, `full_name`, `stars` |
| Activity Metrics | `commits`, `forks`, `watchers`, `open_issues`, `open_pull_requests`, `releases`, `contributors`, `subscribers_count`, `network_count` |
| Project Metadata | `language`, `size`, `created_at`, `updated_at`, `description`, `homepage`, `license`, `topics` |
| Boolean Flags | `has_wiki`, `has_pages`, `is_fork`, `archived` |

---

## Output

The final dataset is saved directly to `data/raw/github_repositories.csv`. This builds the raw dataset required for the `src/features/preprocess.py` script.
